## Deliverable 2 · Closed-circuit wiring (Arc READ / WRITE / ACT)

Arc = the chat box on Dashboard 03. It has no backend, so READ/WRITE/ACT are all **No** everywhere today. Below is what the *data layer* permits once a backend exists — i.e. how far each page is from closed-circuit.

| Page | Data readable by API | Writable by API | Actionable (trigger) | Biggest gap |
|---|---|---|---|---|
| Dashboard / Urgent | Partial · `urgent-actions.json` static; ticks in KV `blocks` | Partial · `api/state` only | No | Blocks have no API of their own; Arc can't create a block server-side. |
| Calendar | Yes · `calendar-events.json` + KV `events` | Partial · reminders via `event-reminder`; events only via `state` | Yes · queue reminder | No `api/events.js` CRUD; the ICS feed ignores locally added events. |
| EE / EHV / PE | Yes · `pages.json` | No · static file, read-only on Vercel | No | Jobs are 5 hard-coded rows. No jobs store at all. |
| CRM / Leads | Yes · `leads-list` | Yes · `leads-append`, webhooks | Partial · SLA flag, undo | `leads-append` writes to filesystem — read-only in prod, so prod writes silently fall back to localStorage. Move to KV. |
| Marketing | Yes · analytics + plan JSON | Partial · calendar cells → KV `mcal` | No | Analytics API is a stub returning the JSON file. |
| Finance | Yes · grid/summary APIs | Yes · `finance-grid` POST | Yes · reminders, Xero match | Xero OAuth expired; `finance-grid` POST also writes filesystem → same prod problem as leads. |
| Compliance / Safety / Legal | Yes · `pages.json` | No | No | Pure display. Expiry dates live in `documents.json` separately from the compliance rows — two sources of truth. |
| eDocuments | Yes · `docs-expiry` | No | No | Read-only listing. |
| Health | Yes · `health-log` | Yes | No | Fine. Training plan is static JSON. |
| Brain | No API | No | No | Most siloed page. Static rows; voice capture doesn't land here. |
| Settings | Yes · `integrations` | Partial · push, passcode | Yes · export, lock | OK. |

Decorative-Arc flag: **all pages.** The chat log is in-memory React state, lost on reload, no context passed, no tools.

Structural wiring faults:
1. Three write paths (`leads-append`, `finance-grid`, `finance-reminders`) write to `data/*.json` on disk — read-only in Vercel prod. They fail silently and the UI falls back to localStorage, so prod edits never reach another device.
2. `api/state` seeds localStorage once and never re-syncs — devices drift.
3. `_auth.guard` protects `state`, `audit`, `health-log`, `push-subscribe`, `export` only. `leads-append`, `finance-grid`, `event-reminder`, `finance-reminders` are unguarded.
4. Frontend duplicates `integrations.json` inline (line ~1425) — two copies to keep in sync.

## Deliverable 3 · 10 improvements ranked by leverage

**1. Arc backend with tools (`api/arc.js`)**
Why: Every other item is worthless until Arc can actually call Claude with tools.
Unlocks: Arc reads any data file, writes via the existing APIs, triggers crons — the entire closed circuit.
Effort: Medium. Touches: Dashboard 03, every page (context injection), new `api/arc.js`.
Build note: tool list = `read_data(file)`, `list_leads`, `append_lead`, `patch_bill`, `create_block`, `create_event`, `queue_reminder`, `search`. Persist log to KV `arc.log`. Pass current `view` + visible rows as system context.

**2. Move all writes to KV — one `api/store.js` CRUD for every entity**
Why: Prod writes currently fail silently (read-only FS). This is a data-loss bug, not a feature gap.
Unlocks: Real multi-device sync, Arc write access, audit that actually reflects reality.
Effort: Small–Medium. Touches: `leads-append`, `finance-grid`, `finance-reminders`, `state`, frontend fallbacks.

**3. Jobs store + Operations page**
Why: EE/EHV pages show 5 hard-coded rows; jobs are the unit of work for both companies and don't exist as data.
Unlocks: Job detail, scheduler, invoice generation, Arc "what's on this week" — all downstream of a jobs entity.
Effort: Large. Touches: new `data/jobs.json` → KV, EE, EHV, Dashboard, Calendar (install dates become events), new Operations page.

**4. Global search + Cmd+K (one component)**
Why: 14 pages and growing; navigation is sidebar-only. Search + palette share the same index.
Unlocks: Jump anywhere, find any lead/bill/event/doc/note in one keystroke; the same index feeds Arc's `search` tool.
Effort: Small. Touches: sidebar, new overlay, in-memory index built from already-loaded state.

**5. Inbox via MS Graph → action extraction**
Why: Outlook is "connected" but nothing reads it. Email is where most work arrives.
Unlocks: Arc triages mail into work blocks, leads, calendar events; drafts replies from contact history.
Effort: Medium. Touches: new `api/mail.js` (reuses `MS_GRAPH_TOKEN`), new Inbox page, Urgent (auto-blocks), CRM (auto-leads).

**6. Brain as real notes: capture, tag, search, voice → note**
Why: Only page with no API and no input. Voice capture bypasses it.
Unlocks: Everything Caleb says or types becomes retrievable; Arc's memory layer.
Effort: Small. Touches: Brain page, `api/notes.js` (KV), voice capture routing, search index.

**7. Bi-directional sync + offline write queue**
Why: `state` seeds once; offline writes vanish. Sync is currently a one-shot.
Unlocks: iPhone edit shows on laptop; site-day edits with no signal land when back in range.
Effort: Medium. Touches: `persist()`, `componentDidMount`, `sw.js` (Background Sync), `api/state`.

**8. Unified notifications feed**
Why: Reminders go out via SMS/email/push but nothing is visible in-app; the data-status banner is the only in-app alert.
Unlocks: One stream — reminder fired, lead SLA breached, doc expiring, Xero disconnected, cron failed — and Arc can post to it.
Effort: Small. Touches: new `api/feed.js` (KV list, every cron appends), Dashboard, Settings.

**9. Rules engine (if-this-then-that, JSON-defined)**
Why: Automations exist but are hard-coded in three different files.
Unlocks: "Lead from Meta with value > $20k → block + SMS"; "Doc expires < 30 d → block"; Arc can author rules.
Effort: Medium. Touches: new `data/rules.json`, `api/rules-run.js` on a cron, Settings (rule list).

**10. Recurring events + tasks, and inbound calendar read**
Why: Every toolbox talk, SWMS review, BAS, and training session recurs. ICS is outbound only.
Unlocks: Calendar stops being a manual entry surface; Arc can do meeting prep off a real agenda.
Effort: Medium. Touches: Event panel (RRULE), `event-reminder`, `calendar-ics`, new inbound ICS/Graph read.

Not listed (already exist under another name): export/backup, audit log, undo, weekly digest, voice capture, push notifications, lead SLA, doc expiry.
